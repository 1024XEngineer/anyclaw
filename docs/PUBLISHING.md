# AnyClaw Marketplace Publishing

This document describes the first production-ready publishing workflow for AnyClaw Cloud Marketplace.

## Current Contract

The current registry publish API accepts artifact metadata, not an uploaded binary package:

```text
POST /v1/publish
Authorization: Bearer <publisher-token>
Content-Type: application/json
```

The request body is:

```json
{
  "artifact": {
    "id": "cloud.skill.example-release-notes",
    "kind": "skill",
    "name": "Example Release Notes Skill",
    "summary": "Turns git history into a changelog draft.",
    "latest_version": "1.0.0",
    "risk_level": "low",
    "trust_level": "verified",
    "permissions": ["fs.read", "git.read"],
    "compatibility": {
      "anyclaw_min": "0.1.0",
      "os": ["windows", "linux", "darwin"],
      "arch": ["amd64", "arm64"]
    }
  },
  "versions": [
    {
      "version": "1.0.0",
      "permissions": ["fs.read", "git.read"]
    }
  ]
}
```

After publish, the registry writes a local package under its durable package directory and fills `size_bytes` and `checksum_sha256`.

## Token Flow

Only an administrator creates publisher tokens:

```powershell
.\scripts\registry-create-publisher-token.ps1 `
  -BaseUrl http://127.0.0.1:8791 `
  -AdminToken $env:ANYCLAW_REGISTRY_ADMIN_TOKEN `
  -PublisherId "AnyClaw Labs"
```

The returned token is shown once. Store it outside git.

Revoke or rotate a publisher token:

```powershell
.\scripts\registry-revoke-publisher-token.ps1 `
  -BaseUrl http://127.0.0.1:8791 `
  -AdminToken $env:ANYCLAW_REGISTRY_ADMIN_TOKEN `
  -TokenId token-20260507120000.000000000
```

Publishers use only the publisher token:

```powershell
.\scripts\registry-publish-artifact.ps1 `
  -BaseUrl http://127.0.0.1:8791 `
  -PublisherToken $env:ANYCLAW_PUBLISHER_TOKEN `
  -Manifest examples/marketplace/skill-release-notes/anyclaw.artifact.json
```

## Web Admin MVP

Round 17 adds a minimal web admin console at `/admin`.

- The route is not linked from public navigation.
- The admin token is typed manually and kept only in the current page state.
- The token is required for artifact management, quarantine, audit, downloads, and publisher token metadata.
- Publisher tokens are still shown only once when created. The token list returns metadata only and does not expose token secrets.
- Publishers should receive publisher tokens, not the registry admin token.

## Required Fields

Artifact:

- `id`
- `kind`: `agent`, `skill`, or `cli`
- `name`
- `summary`
- `latest_version`
- `risk_level`
- `trust_level`
- `permissions`
- `compatibility`

Version:

- `version`
- `permissions`
- `compatibility`
- `signature` is optional metadata for the current round. It is returned by resolve and download headers when present.

The registry fills `size_bytes` and `checksum_sha256` for generated packages. Clients now require `checksum_sha256`; a package without checksum metadata is blocked before download.

## Package Layout Generated By Registry

The built-in local registry storage creates:

```text
anyclaw.artifact.json
README.md
agent/profile.json       # for agent
skill/SKILL.md           # for skill
cli/command.json         # for cli
```

This is enough for the current install/download path. Uploading a real publisher-provided zip is a future enhancement and must be confirmed separately because it changes storage and validation behavior.

## Smoke Checklist

1. Create a publisher token.
2. Publish one skill manifest.
3. Check `GET /v1/artifacts?q=<id>`.
4. Resolve it with `POST /v1/artifacts/{id}/resolve`.
5. Download the returned package.
6. Verify the downloaded SHA256 equals `checksum_sha256`.
7. Confirm admin audit contains `artifact.published`.

## Publisher Safety Notes

- Keep permissions narrow and explicit. High-risk permissions such as `process.exec`, `desktop.control`, `network.any`, `secrets.read`, and `fs.delete` trigger a separate user acknowledgement in the client.
- If an artifact must be removed from circulation, use admin quarantine first. Quarantined artifacts cannot be resolved or downloaded.
- Package signing is documented in `docs/SECURITY.md`. Round 18 does not require publisher-side signing tools yet.
