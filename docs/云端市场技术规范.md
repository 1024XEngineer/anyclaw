## 零、一致性裁决（本主题单一真相源）

本节是 5 份文档之间的**统一裁决**，后文 API / 数据 / 事件 / 流程若有冲突，以本节为准。

### 0.1 绑定目标与 `main_agent`

- `BindingTargetType` 统一为：`main_agent | persistent_subagent | workspace | runtime_global`
- `main_agent` 的持久化语义固定为：**当前 workspace 下 active main-agent profile**
- UI 可以提交 `{ "type": "main_agent" }`，但 Gateway 受理时必须扩展为 `{ "type": "main_agent", "id": "<active_main_agent_profile_id>" }`
- 若无法解析 active main-agent profile id，返回 `400 INVALID_BINDING_TARGET`
- `bindings.target_id` 与 receipt 内的 binding target `id` 保持 `NOT NULL`

### 0.2 RefreshScope 与持久化边界

- `RefreshScopeKind` 统一为：`global | workspace | agent | session`
- `session` 仅表示 **P3 热加载内部刷新粒度**，不是持久化 binding target，也不写入 binding / receipt
- P1 / P2 对外仅允许 `global | workspace | agent`

### 0.3 Artifact 聚合状态

`Artifact.Status / Bound / Active` 是**派生字段**，统一由本地聚合器从 `receipt + bindings + quarantined` 计算，上层禁止自行重算。

| 输入 | 派生 `Artifact.Status` |
| --- | --- |
| 无有效 receipt，或最新有效 receipt = `uninstalled` | `available` |
| receipt = `installing` | `installing` |
| receipt = `rolled_back` | `rolled_back` |
| receipt = `failed` | `error` |
| quarantined 标记存在 | `quarantined` |
| receipt = `installed` 且 0 binding | `installed` |
| receipt = `installed` 且存在 `active` binding | `active` |
| receipt = `installed` 且无 `active`，但存在 `bound` | `bound` |
| receipt = `installed` 且所有 binding 都是 `disabled` | `disabled` |

优先级固定为：`quarantined > installing > rolled_back > failed/error > installed分支`。  
`Bound = (存在至少一个 binding)`；`Active = (存在至少一个 active binding)`。

### 0.4 请求事实字段、决策字段、触发方字段

- `binding_targets` 全文统一为对象数组：`[{ "type": "...", "id": "..." }]`
- 请求侧只表达事实，不表达最终决策
- `user_confirmed: bool` 表示 Ask 弹窗是否已被用户确认
- `decision` 只表示 `DecisionPolicy` 输出，统一枚举：`auto | ask | block`
- `installed_by` 只表示触发方，统一枚举：`user | agent | system`
- 不再使用 `decision = user_confirmed` 或 `installed_by = auto`

### 0.5 Job 终态与回滚

- Job 状态统一为：`pending | running | rolling_back | succeeded | failed | canceled | rolled_back | interrupted`
- 失败且进入 Saga 补偿：`running -> rolling_back -> rolled_back`
- 无副作用失败（如 `Resolve` 失败、`Decide=Block`）：直接 `failed`
- `Refresh` 失败不改变主 Job 成功语义，仍算安装成功，另发刷新失败事件
- **补偿本身失败**：不新增状态，仍落 `failed`，但 `error.code = COMPENSATION_FAILED`，并在 `error.details` 中保留：
  - `original_code`：原始失败码（如 `INSTALL_FAILED`）
  - `compensation_step`：补偿到哪一步失败（如 `Port.Uninstall`）
  - `partial_state`：当时残留的本地状态摘要（用于人工恢复）
- `canceled`：用户 / 系统主动取消
- `interrupted`：进程崩溃恢复扫描出来的"running 但无 owner"

### 0.6 事件命名

所有事件必须带域前缀，统一清单：

- `artifact.installed`
- `artifact.installation_failed`
- `artifact.rolled_back`
- `artifact.uninstalled`
- `artifact.uninstallation_failed`
- `binding.applied`
- `binding.failed`
- `binding.removed`
- `capability.refreshed`
- `capability.refresh_failed`
- `policy.decision`
- `agent.market_tool_called`
- `job.state_changed`

升级不单独定义新事件，仍使用 `artifact.installed`，并在 payload 中带 `operation: install | upgrade | restore`。

### 0.7 同步接口与事件 / Job 的关系

- **同步接口**：`POST /market/uninstall`、`POST /market/bindings`、`DELETE /market/bindings/{id}` 在 P1 / P2 统一为同步：
  - 成功：`200 OK` + 资源体（`Receipt` / `Binding`）
  - 失败：HTTP 错误码（如 `409 LOCAL_VERSION_CONFLICT` / `400 INVALID_BINDING_TARGET`）
- **同步接口仍发审计事件**：成功 / 失败都经 EventBus → AuditLogger 落库，UI 也通过 SSE 接收
  - 卸载成功 → `artifact.uninstalled`
  - 卸载失败 → `artifact.uninstallation_failed`（**不阻塞** HTTP 返回）
  - 绑定失败 → `binding.failed`
- **不进入 Job 状态机**：`jobs.type` 仅含 `install | upgrade | auto_supplement`，不含 `uninstall / bind / unbind`
- 安装 / 升级仍是异步 Job

> **设计原则**：HTTP 通道是**入口契约**，事件通道是**审计契约**，二者并存不冲突。

### 0.8 Resolve 可重试语义（按错误码）

Pipeline 重试策略**只看错误码**，不看步骤：

| 错误码 | 来源 | 可重试 | 说明 |
| --- | --- | --- | --- |
| `NETWORK_UNREACHABLE` | 客户端本地 | 是 | 指数退避 |
| `UPSTREAM_TIMEOUT` | 504 | 是 | 指数退避 |
| `RATE_LIMITED` | 429 | 是 | 必须遵守 `Retry-After` |
| `BAD_GATEWAY` | 502 | 是 | 指数退避 |
| `SERVICE_UNAVAILABLE` | 503 | 是 | 指数退避 |
| `INTERNAL_ERROR` | 500 | 是 | 指数退避 |
| `ARTIFACT_NOT_FOUND` | 404 | 否 | 立即失败 |
| `VERSION_NOT_FOUND` | 404 | 否 | 立即失败 |
| `NO_COMPATIBLE_VERSION` | 409 | 否 | 立即失败 |
| `ARTIFACT_BLOCKED` | 403 | 否 | 立即失败 |
| `POLICY_BLOCKED` | 客户端本地 | 否 | 立即失败 |
| `CHECKSUM_MISMATCH` / `SIGNATURE_INVALID` | 客户端本地 | 否 | 立即触发回滚 |

重试上限：**3 次**指数退避（除 `429` 按 `Retry-After`）。

### 0.9 接口完整性

- 本地网关**必须**提供 `GET /market/artifacts/{id}/versions`，供升级确认页读取 `changelog / permissions_diff / compatibility`
- `MarketAPIFacade` **必须**实现：`HandleArtifactDetail / HandleArtifactVersions / HandleUpgrade / HandleRefresh / HandleInstalled / HandleJobsList / HandleJobCancel`
- 三类 SourceAdapter（Agent / Skill / CLI）**全部**提供：`GetDetail / ListVersions`

## 一、远端协议契约 v1（RemoteRegistryProtocol v1）

### 1.1 协议总则

#### 1.1.1 传输层

- 全部走 HTTPS
- 客户端 → Registry：REST + JSON
- Registry → 客户端：JSON 或重定向（下载 302 → 对象存储签名 URL）

#### 1.1.2 必选 HTTP Header

| Header | 含义 | 示例 |
| --- | --- | --- |
| `X-Protocol-Version` | 协议版本 | `1.0` |
| `X-Client` | 客户端标识 | `anyclaw/0.9.3 (windows; amd64)` |
| `Authorization` | 鉴权（可选） | `Bearer <token>` |
| `Idempotency-Key` | 幂等键（**所有写接口必填**） | `uuid` |
| `X-Request-Id` | 请求追踪 | `uuid` |
| `Accept-Language` | 文案语言 | `zh-CN, en;q=0.5` |

#### 1.1.3 响应头

| Header | 含义 |
| --- | --- |
| `X-Protocol-Version` | 服务端协议版本 |
| `X-Request-Id` | 与请求一致 |
| `X-Trace-Id` | 服务端 trace |
| `Cache-Control` | 缓存策略 |
| `ETag` | 弱缓存标识 |

#### 1.1.4 字符编码

- UTF-8，JSON 严格按 RFC 8259
- 时间字段：RFC 3339 `2026-04-29T12:34:56Z`
- ID：URL-safe，长度 ≤ 128

### 1.2 鉴权

- 公开接口（catalog / detail / 公开包下载）：无需 token
- 私有接口（私有源 / 个人收藏 / 安装统计上报）：`Bearer <token>`
- Token 由 AnyClaw 桌面壳通过设备绑定流程获取（不在本协议范围）

### 1.3 路径规范

- 全部以 `/v1/` 开头
- 资源型 path：`/v1/<resource>/<id>`
- 操作型 path：`/v1/<resource>/<id>/<action>`

### 1.4 通用响应包装

#### 成功

```json
{
  "data": { /* 业务数据 */ },
  "meta": {
    "request_id": "...",
    "ts": "2026-04-29T12:34:56Z"
  }
}
```

列表型：

```json
{
  "data": {
    "items": [ /* ... */ ],
    "total": 1234,
    "cursor": "..."
  },
  "meta": { /* ... */ }
}
```

#### 错误

```json
{
  "error": {
    "code": "ARTIFACT_NOT_FOUND",
    "message": "Artifact does not exist",
    "details": { "artifact_id": "publisher/name" },
    "retryable": false,
    "request_id": "...",
    "trace_id": "..."
  }
}
```

### 1.5 版本演进规则

- **minor 版本（1.0 → 1.1）**：仅新增字段、新增可选 header、新增可选错误码 → 客户端必须**忽略未知字段**
- **deprecated 字段**：响应中保留至少 2 个 minor 版本，注释 `// deprecated since 1.x, use ...`
- **major 版本（1.x → 2.0）**：全新路径前缀 `/v2/`，旧路径同时保留至少 6 个月
- 客户端必须断言响应 header 中的 `X-Protocol-Version` 主版本号匹配，否则拒绝处理

### 1.6 限流

- Registry 可在响应头返回：
  - `X-RateLimit-Limit`
  - `X-RateLimit-Remaining`
  - `X-RateLimit-Reset`
- 触发限流：`429 RATE_LIMITED` + `Retry-After: <seconds>`

## 二、错误码表

### 2.1 设计原则

- 错误码全大写、下划线分隔
- 一一映射 HTTP status
- 标注 `retryable: true | false`
- 客户端按 `code` 决策，**不解析 message**

### 2.2 完整错误码表

| 错误码 | HTTP | retryable | 说明 |
| --- | --- | --- | --- |
| `ARTIFACT_NOT_FOUND` | 404 | 否 | artifact 不存在或已下架 |
| `VERSION_NOT_FOUND` | 404 | 否 | 指定版本不存在 |
| `NO_COMPATIBLE_VERSION` | 409 | 否 | 无与客户端兼容的版本 |
| `ARTIFACT_BLOCKED` | 403 | 否 | 服务端拉黑 |
| `DOWNLOAD_DENIED` | 403 | 否 | 不允许下载（私有/许可） |
| `CHECKSUM_MISMATCH` | 422 | 否 | 客户端校验失败（注：服务端通常不发，由客户端 Verify 触发本地等价） |
| `SIGNATURE_INVALID` | 422 | 否 | 签名验证失败 |
| `PROTOCOL_VERSION_UNSUPPORTED` | 400 | 否 | 客户端协议版本不支持 |
| `INVALID_QUERY` | 400 | 否 | 查询参数非法 |
| `INVALID_BODY` | 400 | 否 | 请求体非法 |
| `MISSING_IDEMPOTENCY_KEY` | 400 | 否 | 写接口缺 Idempotency-Key |
| `UNAUTHORIZED` | 401 | 否 | 未登录或 token 失效 |
| `FORBIDDEN` | 403 | 否 | 无权访问 |
| `NOT_FOUND` | 404 | 否 | 通用 not found |
| `CONFLICT` | 409 | 否 | 状态冲突 |
| `PRECONDITION_FAILED` | 412 | 否 | If-Match / ETag 不匹配 |
| `RATE_LIMITED` | 429 | 是 | 限流（带 retry-after） |
| `INTERNAL_ERROR` | 500 | 是 | 服务端内部错误 |
| `BAD_GATEWAY` | 502 | 是 | 上游错误 |
| `SERVICE_UNAVAILABLE` | 503 | 是 | 服务不可用 |
| `UPSTREAM_TIMEOUT` | 504 | 是 | 上游超时 |

### 2.3 客户端本地错误码

以下错误由客户端在本地产生（不来自服务端）：

| 错误码 | HTTP（Gateway 返回时） | retryable | 含义 |
| --- | --- | --- | --- |
| `NETWORK_UNREACHABLE` | 503 | 是 | 网络不通 |
| `CIRCUIT_OPEN` | 503 | 是 | 熔断器开 |
| `INVALID_BINDING_TARGET` | 400 | 否 | binding target 无法解析或 `main_agent` 归一化失败（见 §0.1） |
| `LOCAL_DISK_FULL` | 507 | 否 | 本地磁盘满 |
| `LOCAL_PERMISSION_DENIED` | 500 | 否 | 本地写权限不足 |
| `LOCAL_DEPENDENCY_MISSING` | 412 | 否 | 本地依赖缺失 |
| `LOCAL_VERSION_CONFLICT` | 409 | 否 | 与已装版本冲突 |
| `POLICY_BLOCKED` | 403 | 否 | 本地策略拒绝 |
| `DOWNLOAD_FAILED` | 502 | 是 | 下载失败（IO / 超时 / 大小不符） |
| `CHECKSUM_MISMATCH` | 422 | 否 | 本地校验和不匹配（触发回滚） |
| `SIGNATURE_INVALID` | 422 | 否 | 本地签名校验失败（触发回滚） |
| `INSTALL_FAILED` | 500 | 否 | Capability Port 落地失败（触发回滚） |
| `RECEIPT_FAILED` | 500 | 否 | 写 receipt 失败 |
| `RUNTIME_REFRESH_FAILED` | 500 | 是 | 刷新 runtime 失败（不阻塞主 Job 成功） |
| `COMPENSATION_FAILED` | 500 | 否 | Saga 反向补偿本身失败（见 §0.5），`details` 必带 `original_code` |
| `JOB_CANCELED` | 409 | 否 | Job 被取消 |
| `JOB_INTERRUPTED` | 500 | 否 | Job 被中断（进程崩溃恢复） |

### 2.4 错误处理决策

- `retryable: true` → 客户端**自动**指数退避重试（最多 3 次）
- `retryable: false` → 客户端**不自动**重试，提示用户
- `429` 必须遵守 `Retry-After`
- 熔断器：连续 5 次 5xx 触发 open，10s 后 half-open

#### 状态机（存储态）

`installing → installed | rolled_back | failed | uninstalled | quarantined`

> 这里是 receipt 自身的**存储态**。`Artifact.Status`（领域态）按 §0.3 派生表从 receipt + bindings + quarantine 计算，**禁止上层把 `receipt.status` 直接当 `Artifact.Status`**。

### 4.3 SQLite Schema

```sql
-- 4.3.1 已安装索引
CREATE TABLE installed (
  id              TEXT PRIMARY KEY,            -- artifact_id
  kind            TEXT NOT NULL,
  version         TEXT NOT NULL,
  source          TEXT NOT NULL,
  receipt_ref     TEXT NOT NULL,               -- receipt 文件相对路径
  installed_at    DATETIME NOT NULL,
  installed_by    TEXT NOT NULL,               -- user | agent | system
  decision        TEXT NOT NULL,               -- auto | ask | block
  risk_level      TEXT,
  trust_level     TEXT,
  status          TEXT NOT NULL,
  updated_at      DATETIME NOT NULL
);
CREATE INDEX idx_installed_kind ON installed(kind);
CREATE INDEX idx_installed_status ON installed(status);

-- 4.3.2 绑定
CREATE TABLE bindings (
  id              TEXT PRIMARY KEY,            -- uuid
  artifact_id     TEXT NOT NULL,
  artifact_kind   TEXT NOT NULL,
  target_type     TEXT NOT NULL,               -- main_agent | persistent_subagent | workspace | runtime_global
  target_id       TEXT NOT NULL,
  version         TEXT NOT NULL,
  source          TEXT NOT NULL,
  receipt_ref     TEXT NOT NULL,
  installed_via   TEXT NOT NULL,
  decision        TEXT NOT NULL,               -- auto | ask | block
  status          TEXT NOT NULL,               -- bound | active | disabled
  created_at      DATETIME NOT NULL,
  updated_at      DATETIME NOT NULL,
  FOREIGN KEY (artifact_id) REFERENCES installed(id)
);
CREATE INDEX idx_bindings_artifact ON bindings(artifact_id);
CREATE INDEX idx_bindings_target ON bindings(target_type, target_id);

-- 4.3.3 Job
CREATE TABLE jobs (
  id              TEXT PRIMARY KEY,            -- uuid
  type            TEXT NOT NULL,               -- install | upgrade | auto_supplement
  state           TEXT NOT NULL,               -- pending | running | rolling_back | succeeded | failed | canceled | rolled_back | interrupted
  current_step    TEXT,
  progress        REAL DEFAULT 0,
  idempotency_key TEXT UNIQUE,
  artifact_id     TEXT,
  version         TEXT,
  error_code      TEXT,
  error_message   TEXT,
  error_details   TEXT,                        -- JSON
  created_at      DATETIME NOT NULL,
  updated_at      DATETIME NOT NULL,
  finished_at     DATETIME
);
CREATE INDEX idx_jobs_state ON jobs(state);
CREATE INDEX idx_jobs_artifact ON jobs(artifact_id);

-- 4.3.4 Outbox
CREATE TABLE outbox (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  event_name      TEXT NOT NULL,
  payload         TEXT NOT NULL,               -- JSON
  trace_id        TEXT,
  created_at      DATETIME NOT NULL,
  delivered_at    DATETIME,
  attempts        INTEGER DEFAULT 0
);
CREATE INDEX idx_outbox_pending ON outbox(delivered_at) WHERE delivered_at IS NULL;
```

## 七、测试策略

### 7.1 测试金字塔

- **单元测试**：每个模块 ≥ 70% 覆盖
- **集成测试**：UseCase 端到端 + Mock Registry
- **契约测试**：协议层用 OpenAPI schema 校验请求/响应
- **E2E 测试**：UI → Gateway → UseCase → 落地

### 7.2 单元测试要求

- 正常路径
- 每条失败语义对应的错误路径
- 边界值（空 / nil / 极大）
- 幂等性（如声明）

### 7.3 集成测试

#### Mock Registry

提供 `pkg/marketplace/registry/mock/` 实现 `RegistryClient` 接口：

- 可配置 fixture 响应
- 可注入错误（按 path / count）
- 可模拟超时与限流

- 完整安装链路（5 步全过）
- Verify 失败 → Saga 回滚
- Install 失败 → Saga 回滚 + receipt rolled_back
- Idempotency 重复提交 → 同一 JobID
- Outbox 进程崩溃后恢复
- Job 取消 / 中断恢复
- Multi-source 聚合
- Cache 命中 / 失效

### 7.4 E2E 测试

- 桌面壳 → /market/control-plane
- 桌面壳 → /market/artifacts → /market/install → /market/jobs/{id}
- Skill 安装后 `delegate_task` 选中（下一轮）

- /market/artifacts 在 2k 条件下 P99 ≤ 200ms（含远端）
- /market/install 提交 P99 ≤ 50ms（异步立即返回）

- 篡改 checksum → Verify 失败 → 不落地

| --- | --- | --- |
| C1 | 当前会话装 Skill 后**不退会话**下一条消息可用 | E2E |
| C2 | Agent 安装后立即出现在 `AvailableAgentNames()` | 集成 |
| C3 | Tool registry 在不重建 runtime 下出现新工具 | 集成 |
| C4 | 失败的热加载不影响已有会话 | 集成 |
| C5 | `RefreshByAgent` 不冲掉其他 workspace 状态 | 集成 |

### 9.4 Phase 4 验收（D1–D5）

| ID | 验收点 | 验证方式 |
| --- | --- | --- |
| D1 | 第三方上传 Agent 包并通过审核 | 服务端 E2E |
| D2 | 签名失败的包被 Block | 集成 |
| D3 | 私有可见性的包仅授权用户能下载 | 集成 |
| D4 | OpenClaw 接入同一 Registry 完成安装 | E2E |
| D5 | 市场端有完整的安装 / 下载统计 | 服务端 |

### 9.5 横向验收（贯穿所有阶段）

- **可观测性**：每个 UseCase 失败可在 trace 内定位到 step
- **审计**：每个状态变化在 audit 文件 100% 出现
- **幂等**：相同 Idempotency-Key 重复提交返回同一 JobID
- **Outbox**：进程崩溃后未发布事件全部追播
- **协议版本**：协议版本不匹配的响应被客户端拒绝

## 十二、附录：失败语义大全

> 事件名按 §0.6；可重试按 §0.8；Job 状态按 §0.5；同步接口与事件并存按 §0.7。

### 12.1 安装失败语义矩阵

| 失败位置 | 错误码 | 可重试 | 补偿 | Job 终态 | receipt 终态 | 事件 |
| --- | --- | --- | --- | --- | --- | --- |
| Resolve（业务） | `ARTIFACT_NOT_FOUND / NO_COMPATIBLE_VERSION / VERSION_NOT_FOUND` | 否 | 无 | `failed` | 无 receipt | `artifact.installation_failed` |
| Resolve（网络 / 上游） | `NETWORK_UNREACHABLE / UPSTREAM_TIMEOUT / RATE_LIMITED / BAD_GATEWAY / SERVICE_UNAVAILABLE` | 是 | 无 | 重试耗尽 → `failed` | 无 | `artifact.installation_failed` |
| Decide=Block | `POLICY_BLOCKED` | 否 | 无 | `failed` | 无 | `policy.decision`(block) + `artifact.installation_failed` |
| Download | `DOWNLOAD_FAILED` | 是 | 删 tmp | 重试耗尽 → `failed` | 无 | `artifact.installation_failed` |
| Verify | `CHECKSUM_MISMATCH / SIGNATURE_INVALID` | 否 | 删 tmp | `rolling_back → rolled_back` | `rolled_back` | `artifact.rolled_back` |
| Install | `INSTALL_FAILED / LOCAL_PERMISSION_DENIED` | 否 | Port.Uninstall | `rolling_back → rolled_back` | `rolled_back` | `artifact.rolled_back` |
| Receipt | `RECEIPT_FAILED` | 否 | status=rolled_back | `rolling_back → rolled_back` | `rolled_back` | `artifact.rolled_back` |
| 补偿本身失败 | `COMPENSATION_FAILED` | 否 | 无（人工恢复） | `failed`（`details.original_code` 保留原始码） | 视情况停留 | `artifact.installation_failed` |
| Refresh | `RUNTIME_REFRESH_FAILED` | 是 | 无 | `succeeded`（主流程仍成功） | `installed` | `artifact.installed` + `capability.refresh_failed` |

### 12.2 绑定失败语义矩阵

> 绑定接口同步返回；事件**异步**发出做审计，不阻塞 HTTP 响应。

| 失败位置 | 错误码 | 可重试 | 补偿 | HTTP | 事件 |
| --- | --- | --- | --- | --- | --- |
| Validate | `INVALID_BODY / INVALID_BINDING_TARGET` | 否 | 无 | 400 | `binding.failed` |
| Persist | `LOCAL_PERMISSION_DENIED / INTERNAL_ERROR` | 是 | 事务回滚 | 500 | `binding.failed` |
| Apply | `INSTALL_FAILED / RUNTIME_REFRESH_FAILED` | 否 | 删 binding | 500 | `binding.failed` |
| Refresh | `RUNTIME_REFRESH_FAILED` | 是 | 无 | 200（不阻塞主流程） | `capability.refresh_failed` |

### 12.3 卸载失败语义矩阵

> 卸载在 P1 / P2 同步（§0.7）；HTTP 返回错误码，事件并行做审计。

| 失败位置 | 错误码 | 可重试 | 补偿 | HTTP | 事件 |
| --- | --- | --- | --- | --- | --- |
| RemoveBindings | `INTERNAL_ERROR` | 是 | 事务回滚 | 500 | `artifact.uninstallation_failed` |
| Cleanup | `LOCAL_PERMISSION_DENIED` | 否 | receipt(failed) + audit | 500 | `artifact.uninstallation_failed` |
| Receipt | `RECEIPT_FAILED` | 否 | 内存降级 | 500 | `artifact.uninstallation_failed` |
| Refresh | `RUNTIME_REFRESH_FAILED` | 是 | 无 | 200（不阻塞主流程） | `capability.refresh_failed` |
